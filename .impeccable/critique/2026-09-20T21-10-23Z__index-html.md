## Design Specificity Verdict

Grounded. Emphatically. Nothing here transplants. The 640x480 stage, WSC brand block, CAM 04-B / EXTERIOR stamp, the status strip, the amber/blue channel rules, and Arthur's half-res nearest-neighbour upscale form a real semantic system. The period is authored, not applied.

Two breaks: (1) Developer and Credits dialogs render at browser px while the game renders scaled, so inspection type is smaller than game type on large screens, floating outside the bezel as a modern card dashboard. (2) #player-input is required with no novalidate, so empty submit raises Chrome's 2020s tooltip inside the 1995 frame.

Deterministic scan: 52 static findings, 50 at runtime. All CSS hits land in styles.css, not index.html.

False positives rejected for this brief: dark-glow x5 (phosphor bloom is a CRT), repeating-stripes-gradient (scanlines), wide-tracking (pixel fonts require it), 100px shadows (vignette), side-tab (industrial chrome), and ~33 text-occlusion hits that were the stuck boot screen (a second pass with it hidden returned zero).

Real and surviving: text-overflow where p.message-text overflows by 319px, low-contrast at 2.0:1, nested-cards x4, and the 10px state readouts (trust/suspicion values the player must parse).

## Overall Impression

The simulation does beautiful work the screen refuses to show. Arthur remembers eight things and scores the player on contradiction; the player gets one truncated sentence. Biggest opportunity: the gate camera is largest and changes once per playthrough; Arthur is a thumbnail and changes every turn. Swap their proportions.

## What's Working

1. The status language is a real system. #phase-label runs off a state machine that throws on illegal transitions; link status, turn count and barrier state read off the same truth.
2. PortraitAnimator is honest period animation: six talk frames at 125ms (8fps), 3600ms unprompted blink, signal-glitch on exactly BECOME_SUSPICIOUS / THREATEN_PLAYER / END_CONVERSATION.
3. The degrade chain actually degrades. Piper never arrived for either agent; the build dropped to eSpeak and kept running. Provider-error copy restores the player's text and states no turn was consumed.

## Priority Issues

### [P0] Boot blocks all input on a voice download that has a working fallback
js/app.js:516 hard-awaits speechDirector.prepare() before enabling input. No skip button exists in the boot markup. Measured 8% at 87s and 7% at 20s by two independent agents. Regression introduced by commit 9398b6b (Piper moved into boot) plus a4167c6 (voice changed to en_US-danny-low, so nothing is cached).
Why: a first-time player cannot play; breaks Principle 4, and the fallback provably works.
Fix: race prepare() against a ~4s timer, boot on whatever voice is ready, hot-swap Piper when it lands. Move the percentage to #link-status as VOICE 12%.
Command: /impeccable harden

### [P1] There is no conversation history; the player has less memory than the NPC
index.html:117 — #conversation is role="log", visually-hidden, aria-live="off". Subtitle clamps to 3 lines and cuts the gun de-escalation line at "Put it down and…". pendingRequest is tracked in game.js and rendered nowhere.
Why: Arthur's personality is catching contradictions across 8 memories; the player cannot check their own story.
Fix: un-hide as a printer-roll scrollback (spec §5 already asked for a log panel). Stamp pendingRequest into the gate status strip as OUTSTANDING: PRODUCE WORK ORDER.
Command: /impeccable layout

### [P1] The player gets no read on escalation
.status-lamp--red appears once in CSS and zero times across all of js/. Portrait alt text is identical across all nine reaction frames. Tone lives only behind Developer.
Why: the project exists to answer whether the character feels reactive; at peak reactivity the screen shows a green lamp and a repeated sentence.
Fix: wire the existing red lamp to banded state (NOMINAL / ELEVATED / ALERT) per the spec's "no raw numbers" rule. Set alt from portraitCue.
Command: /impeccable clarify

### [P2] One press of Audio permanently destroys the voice lamp
js/app.js:759 — audioToggle.textContent wipes the button's children including #voice-lamp and #voice-engine. Later renderVoiceEngine() calls write to a detached node. Never recovers without a reload, which now costs the P0 boot download.
Fix: write to an inner span, as #send-button already does.
Command: /impeccable polish

### [P2] The most common mistake produces 2020s browser chrome
index.html:134 has required and no novalidate. Empty submit raises Chrome's bubble. app.js also dumps raw error.message into #input-hint, measured at 2.14:1 at 7px — the only place the reset instruction lives.
Fix: drop required, add novalidate, answer in-world via #input-hint (NO CARRIER — TYPE A MESSAGE). Lift the hint to amber at 9px. Route exceptions to #provider-status.
Command: /impeccable harden
